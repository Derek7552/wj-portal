# PDT-391 产品需求文档

> **需求名称**：优化AI漏洞猎人任务异常终止场景的界面展示  
> **需求编号**：PDT-391  
> **优先级**：High  
> **创建日期**：2025-12-28

---

## 1. 需求背景

### 1.1 问题描述

当前漏洞猎人智能体的界面设计只考虑了正常完成流程，但任务中断时，任务详情的对话和智能体空间中存在大量空页面（未提示原因，也没有提示暂无数据）

### 1.2 目标

当任务因系统中断或用户终止，导致的任务中断，需优化界面各部分的预期展示效果，确保用户能够：

- 清晰了解任务中断原因
- 确认数据保存状态
- 了解当前任务状态

---

## 2. 需求模块

### 模块1：在任务异常终止时，通过两个提示区域向用户展示完整的任务状态信息

**阶段执行区域异常提示框**：在Agent执行中断处，展示错误类型和错误信息

**异常终止总结卡片**：独立的对话卡片，包含固定开头、已完成工作和异常原因

### 模块2：产物数据保存和查看提示

**功能**：若生成产物，保存数据在智能体空间中

---

## 3. 平台任务业务状态

### 3.1 业务状态定义

平台任务有以下业务状态：（本次优化的是异常退出和手动终止的提示）

| 业务状态 | 说明 | 使用场景 |
|---------|------|---------|
| 队列中 | 任务已创建，等待执行 | 任务刚创建时 |
| 进行中 | 任务正在执行 | 任务执行过程中 |
| 已完成 | 任务正常完成 | 所有阶段正常完成 |
| 异常退出 | 任务因系统错误而中断 | 系统错误、安全拦截、解析失败等 |
| 手动终止 | 任务被用户手动取消 | 用户点击终止按钮 |

### 3.2 中断场景分类及错误提示文案内容

共支持 **9种异常场景**：

| 中断方式 | 是否有漏洞 | 场景编号 |

| 用户手动取消 | ✅ 有漏洞 | 场景1 |
| 用户手动取消 | ❌ 无漏洞 | 场景2 |
| 系统错误 | ✅ 有漏洞 | 场景3 |
| 系统错误 | ❌ 无漏洞 | 场景4 |
| 安全策略拦截 | ✅ 有漏洞 | 场景5 |

**场景9特殊说明**：

- **发生时机**：用户在新建任务时，因配额用完，任务在创建阶段即被终止，**未开始执行**
- **展示差异**：
  - **不显示第一个提示框**：因为任务未开始执行，没有阶段执行过程，因此不显示阶段执行区域异常提示
  - **只显示第二个提示框**：直接显示异常终止总结卡片
  - **固定开头不同**：使用"非常抱歉，当前任务无法分析。"而非"任务在执行阶段X时遇到异常"
  - **已完成工作**：显示"无（任务未开始执行）"
- **右侧智能体空间**：显示"暂无数据"（因为任务未执行，无任何产物）

#### 3.2.3 右侧智能体空间展示

- **有产物**：显示漏洞报告、已生成的文档
- **无产物**：显示"暂无数据"提示
- **任务进度**：显示已完成阶段✓，未完成阶段✗
- **场景9特殊**：显示"暂无数据"（任务未开始执行）

### 3.3 界面展示规则

所有异常场景的展示逻辑相同，仅提示内容不同：

| 展示区域 | 展示内容 |
|---------|---------|
| **左侧思考过程区域** | 思考过程停留在最后的执行阶段和执行日志。<br>在最后中断的地方，增加异常提示框：展示错误类型和错误信息 |
| **左侧生成区域** | 新增异常终止总结卡片：独立的对话卡片，包含固定开头、已完成工作和异常原因 |
| **右侧智能体空间** | 产物：推送了哪些产物就展示哪些内容（如有）<br>任务进度：显示已完成阶段✓，未完成阶段✗ |

**第一个提示框详细说明**：

- **位置**：在思考过程中（阶段执行日志最后），Agent执行中断处
- **展示内容**：
  - 警告图标：⚠️
  - 异常标题："异常终止"（用户手动终止场景）或"系统异常"（其他异常场景）
  - 错误类型：根据中断方式显示（用户手动取消、内存溢出异常、安全风控拦截、文件解析失败、配额用完）
  - 错误信息：根据中断方式显示具体错误信息
- **视觉样式**：红色横幅（浅红色背景 #fee2e2，红色边框 #dc2626，圆角8px）

**第二个提示框详细说明**：

- **位置**：独立的对话卡片，在阶段执行区域之后（新的时间戳）
- **展示内容**：
  - 卡片标题："❌ 任务异常终止"
  - 固定开头：所有场景都包含，如果有漏洞，在固定开头后添加"您可以在智能体空间中查看漏洞报告。"
  - 已完成的工作：列表，带✓绿色勾选标记，无论是否有漏洞都必须显示
  - 异常原因：列表，带•黑色圆点标记，显示中断原因和建议措施
- **视觉样式**：左侧红色边框（3px solid #dc2626），白色背景

### 3.4 处理流程

```
任务中断事件
    ↓
[模块1] 识别中断场景和原因
    ↓
[模块1] 生成中断提示文案
    ↓
[模块2] 判断是否发现了漏洞，生成查看漏洞报告提示（在固定开头中展示）
    ↓
[模块2] 如果无漏洞但有其他产物，生成查看数据提示
    ↓
更新UI展示
    - 左侧思考过程区域：异常提示框，展示错误类型和错误信息
    - 左侧生成区域：异常终止总结卡片，包含固定开头、已完成工作和异常原因
    - 右侧智能体空间：显示产物（如有）和任务进度
```

- [ ] 第一个提示框正确显示警告图标、异常标题、错误类型和错误信息
- [ ] 不同中断方式下，错误类型和错误信息正确对应（见3.2表格）
- [ ] 第二个异常终止总结卡片正确显示为独立对话卡片
- [ ] 无论是否有漏洞，都必须显示"已完成的工作"
- [ ] 异常原因正确显示，并包含建议措施
- [ ] 右侧智能体空间正确展示已推送的产物，和当前任务进度
- [ ] 无产物，提示暂无数据
- [ ] 有产物，在智能体空间中展示
- [ ] 场景9特殊：不显示第一个提示框，只显示第二个提示框，固定开头为"非常抱歉，当前任务无法分析。"
