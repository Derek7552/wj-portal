# 任务记录通用 UI 设计规范

## 一、元素抽象定义

### 1. 核心元素（所有类型必备）

| 元素 | 说明 |
|------|------|
| 状态 | 任务完成状态 |
| 标题 | 任务名称/描述 |
| 时间 | 使用时间（年月日时分秒） |

### 2. 可选元素

| 元素类型 | 元素 | 说明 |
|----------|------|------|
| 标签 | 来源标签 | 如：本地/仓库 |
| 统计数据 | 数量统计 | 如：漏洞数量 |
| 操作按钮 | 下载 | 下载任务结果 |
| 操作按钮 | 终止 | 终止进行中的任务 |
| 操作按钮 | 删除 | 删除任务记录 |

---

## 二、状态与操作的互斥性

### 1. 状态流转（互斥，同一时刻只能处于一种状态）

```
分析中 ──┬──→ 已完成（成功终态）
         ├──→ 已终止（用户主动终止）
         └──→ 错误（执行失败终态）
```

### 2. 操作按钮与状态的绑定关系

| 操作 | 可用状态 | 不可用状态 | 说明 |
|------|----------|------------|------|
| 终止 | 分析中 | 已完成、已终止、错误 | 仅进行中可终止 |
| 删除 | 已完成、已终止、错误 | 分析中 | 仅终态可删除 |
| 下载 | 已完成 | 分析中、已终止、错误 | 仅成功完成可下载 |

### 3. 操作按钮互斥关系

| 按钮组合 | 关系 | 说明 |
|----------|------|------|
| 终止 vs 删除 | **状态互斥** | 永不同时出现 |
| 下载 vs 删除 | 可共存 | 已完成状态下可同时显示 |
| 下载 vs 终止 | **状态互斥** | 永不同时出现 |

### 4. 通用规则

#### 标题截断规则

| 布局类型 | 最大长度 | 处理方式 |
|----------|----------|----------|
| 单行布局 | 40-50字符 | 超出显示 `...` |
| 双行布局 | 50-60字符 | 超出显示 `...` |
| hover | 无限制 | tooltip 显示完整内容 |

#### 时间显示规则

| 时间范围 | 显示格式 | 示例 |
|----------|----------|------|
| 今天 | `HH:mm` | `14:30` |
| 昨天 | `昨天 HH:mm` | `昨天 14:30` |
| 本年内 | `MM-DD HH:mm` | `01-15 14:30` |
| 跨年 | `YYYY-MM-DD HH:mm` | `2024-12-20 14:30` |

## 四、任务记录类型定义

### Type-A：基础型

**组成** = 状态 + 标题 + 时间 + 终止/删除（互斥）

**状态模式**：多状态（分析中、已完成、已终止、错误）

**条件操作规则**：
- 分析中 → 显示终止按钮
- 已完成/已终止/错误 → 显示删除按钮

**数据类型**：文件类、自然语言类

**适用智能体**：
- 安全论文检索（自然语言类）
- 安全智库（自然语言类）
- 论文翻译（文件类）
- pcap包分析（文件类）
- ctf竞赛（自然语言类）
- 攻击面检查（自然语言类）
- 社工钓鱼（自然语言类）
- 漏洞情报（自然语言类）
- 论文研读（文件类）
- 文档速读（文件类）
- 漏洞通告（自然语言类）

---

### Type-B：基础 + 下载

**组成** = 状态 + 标题 + 时间 + 下载（条件） + 终止/删除（互斥）

**状态模式**：多状态（分析中、已完成、已终止、错误）

**条件操作规则**：
- 分析中 → 显示终止按钮
- 已完成 → 显示下载按钮 + 删除按钮
- 已终止/错误 → 显示删除按钮

**数据类型**：文件类

**适用智能体**：
- 缺陷研判（文件类）

---

### Type-C：复杂型

**组成** = 状态 + 标题 + 标签 + 统计 + 时间 + 终止/删除（互斥）

**状态模式**：多状态（分析中、已完成、已终止、错误）

**数据类型**：代码类

**条件操作规则**：
- 分析中 → 显示终止按钮
- 已完成/已终止/错误 → 显示删除按钮

**适用智能体**：
- AI漏洞猎人（代码类）

## 八、元素展示次序

按信息重要性和用户阅读习惯，采用**双行布局**：

### 主行（第一行）—— 核心信息

```
1. 状态图标 → 2. 标题
```

> 主行只展示最核心的信息，保持视觉简洁

### 副行（第二行）—— 辅助信息

```
3. 标签（可选） → 4. 统计数据（可选） → 5. 时间
```

> 副行展示补充信息，样式统一为次级文本

### 操作区 —— hover 时显示

```
6. 下载（可选） → 7. 终止/删除（互斥）
```

> 操作按钮在 hover 时显示于卡片右侧

## 九、UI 布局设计

### 1. 双行布局结构

> 采用双行布局，将不同类型的信息分层展示，避免单行内样式过于混杂。

**设计原则**：
- 主行突出核心信息（状态 + 标题），样式简洁
- 副行统一为次级文本样式，降低视觉干扰
- 操作按钮 hover 时浮现，不占用常态空间

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  [状态图标]  标题文本...............................................        │ ← 主行
│             仓库 · 漏洞 5 个 · 2025-01-15 14:30           [下载] [删除]    │ ← 副行 + 操作区(hover)
└─────────────────────────────────────────────────────────────────────────────┘

卡片高度: 64px  |  内边距: 12px 16px  |  卡片间距: 8px
```

### 2. 主行设计

| 元素 | 样式 | 说明 |
|------|------|------|
| 状态图标 | 16px 图标 | ✓ 已完成 / ◐ 分析中 / ✕ 已终止 |
| 标题 | 14px 主文本色，单行截断 | 最大宽度自适应，超出显示 `...` |

**布局**：
```
[图标 16px] [间距 8px] [标题 flex:1]
```

### 3. 副行设计

> 副行所有元素统一使用次级文本样式，通过分隔符连接，形成一致的阅读体验。

| 元素 | 样式 | 说明 |
|------|------|------|
| 标签 | 12px 次级文本色 | 如：本地、仓库 |
| 统计 | 12px 次级文本色 | 如：漏洞 5 个 |
| 时间 | 12px 次级文本色 | 相对/绝对时间 |
| 分隔符 | `·` 或 `|` | 元素间分隔 |

**布局**：
```
[左侧留白 24px] [标签] · [统计] · [时间]         [操作按钮区 hover显示]
```

**副行文本拼接规则**：
- 各元素间用 ` · ` 分隔
- 无标签/统计时直接显示时间
- 示例：`仓库 · 漏洞 5 个 · 01-15 14:30`

### 4. 操作按钮设计

- **默认状态**：隐藏操作按钮
- **hover 状态**：操作按钮浮现于副行右侧
- **切换方式**：淡入淡出，transition: 0.2s

```
默认：  仓库 · 漏洞 5 个 · 01-15 14:30
hover： 仓库 · 漏洞 5 个 · 01-15 14:30    [下载] [删除]
```

### 5. 元素显隐配置

| 类型 | 主行 | 副行-标签 | 副行-统计 | 副行-时间 | 操作-下载 | 操作-终止 | 操作-删除 |
|------|------|-----------|-----------|-----------|-----------|-----------|-----------|
| Type-A | 状态+标题 | - | - | ✓ | - | ✓(分析中) | ✓(终态) |
| Type-B | 状态+标题 | - | - | ✓ | ✓(已完成) | ✓(分析中) | ✓(终态) |
| Type-C | 状态+标题 | ✓ | ✓ | ✓ | - | ✓(分析中) | ✓(终态) |

### 4. 状态图标说明

| 图标 | 状态 | 含义 | 可用操作 |
|------|------|------|----------|
| ✓ | 已完成 | 任务成功完成 | 删除、下载（如适用） |
| ◐ | 分析中 | 任务正在执行 | 终止 |
| ✕ | 已终止 | 用户主动终止 | 删除 |
| ❌ | 错误 | 任务执行失败 | 删除 |
